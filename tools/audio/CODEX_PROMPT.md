# Задача для Codex: озвучка слов Ad fontes (иврит + греческий) через Voice Studio

## Контекст
Ad fontes — личное PWA для изучения Библии (репозиторий `elijahflanagan48-hue/scriptorium`, GitHub Pages, https://script.noeon.org, vanilla JS, без сборки). Нужно, чтобы по тапу на слово в оригинале (иврит/греческий) гарантированно звучало слово, а не зависело от голосов iOS. Решение: заранее озвучить слова через Voice Studio (локально, Mac, Apple Silicon), сжать в Opus и подгружать по тапу. Системный голос (speechSynthesis) остаётся запасным вариантом.

Пользователь: Elijah, пишет по-русски, отвечай ему по-русски, коротко. Лимиты у него заканчиваются — работай автономно, без лишних вопросов; решай разумно сам и фиксируй решения в `tools/audio/NOTES.md`.

## Решения пользователя (не пересматривать)
- Иврит — **мужской голос**, греческий — **женский голос**.
- Иврит читать с огласовками (никуд), без кантилляции; произношение современное израильское.
- Греческий — как выдаёт модель (современное чтение политонических слов); спорить с этим не нужно.
- Качество: `steps=32` (на 8 шагах греческое слово «ἀγάπη» получилось шумом — не используй 8). Для фазы 2 (формы) допустимо 16, если 32 слишком медленно, но сначала проверь на выборке на слух-эквивалент (см. проверка).
- Формат: Opus в Ogg, моно, 24 kbps (`ffmpeg -c:a libopus -b:a 24k -ac 1`), ~3–4 КБ на слово. Обрезать тишину по краям, привести громкость (loudnorm до -20 LUFS или простое peak-normalize) — единообразно для всех файлов.

## Что уже подготовлено в репозитории
- `tools/audio/norm.py` — единая нормализация и ID: `id = sha1(norm(text, lang)).hexdigest()[:12]`, файл `<lang>/<id>.opus` (`lang` = `heb` | `grc`). Приложение (speech.js) должно применять ТЕ ЖЕ правила. Не меняй правила без переноса в JS.
- `tools/audio/build_lists.py` → `tools/audio/lists/*.jsonl` (`{"id","text"}` на строку, отсортировано по частоте в тексте):
  - `heb_lemmas.jsonl` 8 139, `grc_lemmas.jsonl` 5 368 — **фаза 1**
  - `heb_forms.jsonl` 50 925, `grc_forms.jsonl` 20 910 — **фаза 2** (все остальные словоформы из текста)

## Как работать с Voice Studio (важные нюансы, уже выяснены)
- Приложение VoiceStudio запущено на Mac, локальный сервер `http://127.0.0.1:3900` (OpenAPI-описание есть в приложении: Настройки → «API VoiceStudio»; есть OpenAI-совместимый speech-эндпоинт). **Предпочтительный путь: написать Python-скрипт, который сам вызывает локальный HTTP API** (ничего не гоняя через контекст ИИ). MCP-инструмент `generate_speech` по умолчанию возвращает base64 прямо в ответ (огромно), режима «files» в UI нет.
- Если используешь MCP: `generate_speech(text, language, steps, profile_id)`: `language` = `"he"` для иврита, `"el"` для греческого. Пакетные `pack_start/pack_status/pack_fetch/pack_asr` тоже работают: в каждой строке `voice` (profile_id) обязателен; `pack_fetch` возвращает большой JSON, который сохраняется во временный файл (поле `tasks[].wav_base64`). `pack_asr` проверяет речь распознаванием, но он настроен на английский, поэтому для проверки греческого/иврита годится только как «есть речь / нет речи».
- Первый вызов после простоя ~10 с (прогрев), дальше ≈1 с на слово при steps=16 и ≈1.5–2 с при 32. Оценка: фаза 1 ≈ 6–8 ч, фаза 2 ≈ 30+ ч. Скрипт обязан быть **возобновляемым** (пропускать уже готовые файлы), писать лог, переживать падения (ретраи, перезапуск) и не держать всё в памяти.
- Голоса: в Voice Studio есть только английские «designed» голоса и клон `demo0001` (тёплый низкий мужской), им пробовали — «норм». Нужно выбрать/создать:
  1. мужской голос для иврита (можно `demo0001` или сделать через `design_voice`/`list_voices`);
  2. женский голос для греческого (создать через `design_voice`, например «female, young adult, moderate pitch», и **заблокировать/сохранить профиль**, чтобы тембр был одинаковый на всех словах — фиксируй `seed`).
  Перед массовой генерацией прогнать по 20 слов на голос и убедиться, что тембр стабилен и слова слышны.

## Проверка качества (обязательна)
- Для каждого файла: длительность 0.2–4 с, RMS не «пустой» (не тишина), нет клиппинга. Файлы, не прошедшие, пометить и перегенерировать (до 3 попыток, затем другой seed).
- Выборочно (≈2%) — `transcribe`/`pack_asr` для проверки, что это речь; результат в `tools/audio/qa_report.md`.
- Эталонные слова для ручной проверки пользователем (положить в `audio_bible/samples/`): ἀγάπη, λόγος, θεός, Ἰησοῦς, בְּרֵאשִׁית, אֱלֹהִים, יְהוָה (читать как «Адонай»? — решение: озвучивать как есть по огласовке и пометить в NOTES), שָׁלוֹם.

## Интеграция в приложение (после фазы 1, отдельным коммитом)
`speech.js` (70 строк, функция `say(text,isH,mode)`): при тапе по слову в оригинале
1. посчитать `id` (sha1 от нормализованного текста — реализовать `norm` на JS идентично `norm.py`, SubtleCrypto `crypto.subtle.digest('SHA-1')`),
2. `fetch(AUDIO_BASE + lang + '/' + id + '.opus')`; при 200 — проиграть через `Audio`/WebAudio (на iOS запуск только из жеста тапа; один общий `Audio`-элемент или AudioContext, разблокированный первым тапом),
3. при 404/ошибке сети — запасной путь `speechSynthesis` как сейчас,
4. `AUDIO_BASE` — константа в начале speech.js (по умолчанию `./audio/`); кэширование: в `sw.js` добавить cache-first для `/audio/` (отдельный кэш с лимитом ~2000 записей, не трогая основной `scriptorium-3`).
Не ломать уже работающие режимы `native`/`tr` (транслитерация кириллицей). Подними `?v=` в index.html. Проверка: Playwright (`/usr/bin/google-chrome`, `python3 -m http.server`), тест с мок-файлом. Деплой: `git fetch && git rebase origin/main && git push`, затем `gh run list -L 1`.
